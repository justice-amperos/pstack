# Continuity across repeated runs

Persist minimal state in the agreed workspace: workflow version, actual coverage, last successful checkpoint, stable finding identities and evidence, current status, completed actions, and decisions awaiting the owner. Keep sensitive raw records out of reusable skills and broadly shared summaries. If durable storage is unavailable, return a carry-forward note and label cross-run deduplication unavailable.

Resume from the last successful checkpoint with enough overlap to catch late arrivals when supported. Deduplicate by stable record/finding identity and material change, not wording. Revisit open findings when new evidence, a due date, or an agreed reminder calls for it. Missing records do not establish resolution without adequate coverage. Do not advance a successful checkpoint across a failed or incomplete interval; record partial coverage separately.

Before retrying an external action, inspect whether it already succeeded. If its outcome cannot be established, hold that action and report uncertainty instead of duplicating it. Use one writer for shared state; reconcile changes rather than overwriting another run.

Honor the requested reporting cadence. Exception-only monitoring stays quiet on unchanged, healthy runs while retaining a run record. Missing coverage, failures, or required decisions are reportable exceptions. A requested digest still gets a concise digest. Notifications and persistent schedules require authorization and a functioning host mechanism.

When accepted criteria change, record the revision and consider whether earlier findings need re-evaluation. Retain the prior interpretation and why it changed. A workflow correction does not authorize unrelated changes or permanently widen the task.
